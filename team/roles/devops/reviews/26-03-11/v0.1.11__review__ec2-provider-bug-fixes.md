# DevOps Review: EC2 Provider Bug Fixes

**Version:** v0.1.11
**Date:** 2026-03-11
**Role:** DevOps

---

## Summary

Fixed 8 bugs in the osbot-aws integration layer (`EC2_Provider__AWS.py`) where return types from osbot-aws methods did not match what the provider expected. These were all discovered by tracing the actual osbot-aws source code against our provider contracts.

## Root Cause

The provider was written against assumed API contracts rather than verified ones. osbot-aws methods have inconsistent return patterns:
- Some return `None` (stop, start, terminate)
- Some return strings instead of dicts (instance_create)
- Some return dicts-keyed-by-id instead of lists (instances_details)
- Some return bools (key_pair_delete)
- Parameter names don't always match what you'd expect (`security_group_id` not `group_id`)

## Lesson Learned

**Always read the osbot-aws source before writing provider methods.** The library doesn't have type annotations, so you can't trust IDE hints. The source at `/usr/local/lib/python3.11/dist-packages/osbot_aws/aws/ec2/EC2.py` is the only reliable contract.

## Remaining Concerns

1. `wait_for_instance_running()` uses `details.get('state', {}).get('Name', '')` — need to verify this matches the actual osbot-aws `format_instance_details()` output structure
2. `security_group_revoke_ingress()` calls `ec2.client()` directly — this bypasses osbot-aws and uses boto3. Should be refactored to use an osbot-aws method if one exists
3. The `list_instances()` return type annotation still says `-> list` but returns a dict — annotation should be updated
