# Architect Brief: Vault Integration for Deploy Service

**Version:** v0.1.12
**Date:** 2026-03-11
**Role:** Architect (Explorer Team)
**Status:** Brief — ready for Dev implementation

---

## Purpose

This brief specifies how `SG_Send__Deploy` integrates with the SG/Send zero-knowledge vault
as its encrypted configuration and secrets store.

Today, deployment-specific data (AMI IDs, security group IDs, budget limits, stage config)
has no persistent, encrypted home. It would end up as GitHub Secrets (opaque, hard to audit),
committed plaintext config files (security risk), or hardcoded defaults (inflexible).

A vault solves all three problems:
- **Encrypted at rest and in transit** — AES-256-GCM, server never sees plaintext
- **Persistent across sessions** — Claude sessions, CI runs, and human operators all share the same source of truth
- **Auditable** — vault has a tree history (commit chain); every write is versioned
- **Access-controlled** — read is open (to anyone with the vault key); write requires token

The vault also enables a future where each data room has its own vault, storing its specific
configuration, branding, and encrypted session state — but that is out of scope for this brief.

## Dependency: sg-send-cli PyPI Package

All vault operations use the `sg-send-cli` PyPI package directly. **Do not shell out to the
CLI binary.** Import and use the Python classes.

```
pip install sg-send-cli
```

**Key classes to use (all from `sg_send_cli`):**

| Class | Import path | What it does |
|-------|-------------|--------------|
| `Vault__Sync` | `sg_send_cli.sync.Vault__Sync` | Core sync engine: `clone`, `pull`, `push`, `status` |
| `Vault__API` | `sg_send_cli.api.Vault__API` | Low-level HTTP: `read`, `write`, `delete` |
| `Vault__Crypto` | `sg_send_cli.crypto.Vault__Crypto` | AES-256-GCM encrypt/decrypt, key derivation |
| `Safe_Str__Vault_Key` | `sg_send_cli.safe_types.Safe_Str__Vault_Key` | Validated vault key type |
| `Safe_Str__Access_Token` | `sg_send_cli.safe_types.Safe_Str__Access_Token` | Validated access token type |

**Factory pattern** (from `CLI__Vault.create_sync` — replicate this, don't import CLI__Vault):

```python
from sg_send_cli.api.Vault__API    import Vault__API
from sg_send_cli.crypto.Vault__Crypto import Vault__Crypto
from sg_send_cli.sync.Vault__Sync  import Vault__Sync

def create_vault_sync(vault_key: str, access_token: str, base_url: str = '') -> Vault__Sync:
    api = Vault__API(base_url=base_url or '', access_token=access_token or '')
    api.setup()                              # sets base_url to DEFAULT_BASE_URL if empty
    return Vault__Sync(crypto=Vault__Crypto(), api=api)
```

## Environment Variables — The Only Two Required

The entire deploy service config lives in the vault. Only two env vars are needed to
bootstrap access to it:

| Env var | Format | Example | Required for |
|---------|--------|---------|--------------|
| `SG_SEND__DEPLOY__VAULT_KEY` | `<passphrase>:<vault_id>` (8 hex chars) | `abc123xyz...:a1b2c3d4` | Read + Write (write_key is derived from passphrase) |
| `SG_SEND__DEPLOY__ACCESS_TOKEN` | Opaque string | `sg_abc...` | Write operations only |

**Key insight:** `Vault__Crypto.derive_keys_from_vault_key(vault_key)` derives `read_key`,
`write_key`, `vault_id`, `tree_file_id`, and `settings_file_id` all from the vault key.
Nothing else needs to be configured.

Read-only operations (status checks, config reads) need only `SG_SEND__DEPLOY__VAULT_KEY`.
Write operations (pushing config updates) additionally need `SG_SEND__DEPLOY__ACCESS_TOKEN`.

If either env var is absent, the service starts and operates in **degraded mode** — it
serves cached/default config and logs a startup warning. It does not crash.

## Vault Directory Layout

The deploy vault follows this file tree. All files are JSON. The vault tree is the source
of truth; the local clone (in a temp working directory on the Lambda/server) is a cache.

```
config/
  ec2.json            # AMI ID, region, security_group_id, allowed instance types
  budget.json         # max_instances, daily_budget_usd, enforce_limits flag
  stages/
    dev.json          # dev-stage overrides (instance type, SG ID, etc.)
    qa.json
    prod.json
state/
  fleet.json          # last-known fleet snapshot (instance IDs + statuses)
```

## New Class: Service__Vault

**Path:** `sg_send_deploy/vault/Service__Vault.py`

This is the single entrypoint for all vault operations in the deploy service. It is
**injected** into routes and other services — never instantiated inline.

```python
import json
import os
import tempfile
from osbot_utils.type_safe.Type_Safe import Type_Safe
from sg_send_cli.api.Vault__API      import Vault__API
from sg_send_cli.crypto.Vault__Crypto import Vault__Crypto
from sg_send_cli.sync.Vault__Sync    import Vault__Sync

ENV__VAULT_KEY   = 'SG_SEND__DEPLOY__VAULT_KEY'
ENV__ACCESS_TOKEN = 'SG_SEND__DEPLOY__ACCESS_TOKEN'


class Service__Vault(Type_Safe):
    vault_key    : str = ''
    access_token : str = ''
    local_dir    : str = ''     # working directory for local clone
    _sync        : object = None  # Vault__Sync instance (not a Type_Safe field)

    def setup(self) -> 'Service__Vault':
        if not self.vault_key:
            self.vault_key    = os.environ.get(ENV__VAULT_KEY   , '')
        if not self.access_token:
            self.access_token = os.environ.get(ENV__ACCESS_TOKEN, '')
        if not self.local_dir:
            self.local_dir = tempfile.mkdtemp(prefix='sg-deploy-vault-')
        return self

    def is_configured(self) -> bool:
        return bool(self.vault_key)

    def can_write(self) -> bool:
        return bool(self.vault_key) and bool(self.access_token)

    def sync(self) -> Vault__Sync:
        if self._sync is None:
            api       = Vault__API(base_url='', access_token=self.access_token)
            api.setup()
            self._sync = Vault__Sync(crypto=Vault__Crypto(), api=api)
        return self._sync

    def clone_or_pull(self) -> dict:
        """Clone on first use; pull on subsequent calls."""
        sg_vault_dir = os.path.join(self.local_dir, '.sg_vault')
        if os.path.isdir(sg_vault_dir):
            return self.sync().pull(self.local_dir)
        else:
            self.sync().clone(self.vault_key, self.local_dir)
            return dict(added=[], modified=[], deleted=[])

    def read_file(self, relative_path: str) -> dict:
        """Read a JSON file from the local vault clone. Returns {} if missing."""
        full_path = os.path.join(self.local_dir, relative_path)
        if not os.path.isfile(full_path):
            return {}
        with open(full_path, 'r') as f:
            return json.load(f)

    def write_file(self, relative_path: str, data: dict) -> None:
        """Write a JSON file to the local clone (does NOT push — call push() separately)."""
        full_path = os.path.join(self.local_dir, relative_path)
        os.makedirs(os.path.dirname(full_path), exist_ok=True)
        with open(full_path, 'w') as f:
            json.dump(data, f, indent=2)

    def push(self) -> dict:
        """Push all local changes back to the remote vault."""
        return self.sync().push(self.local_dir)

    def status(self) -> dict:
        return self.sync().status(self.local_dir)

    def list_files(self) -> list:
        """Return sorted list of relative file paths in the local clone."""
        result = []
        for root, dirs, files in os.walk(self.local_dir):
            dirs[:] = [d for d in dirs if d != '.sg_vault' and not d.startswith('.')]
            for filename in files:
                if filename.startswith('.'):
                    continue
                full_path = os.path.join(root, filename)
                rel_path  = os.path.relpath(full_path, self.local_dir).replace(os.sep, '/')
                result.append(rel_path)
        return sorted(result)

    # --- convenience accessors ---

    def config_ec2(self) -> dict:
        return self.read_file('config/ec2.json')

    def config_budget(self) -> dict:
        return self.read_file('config/budget.json')

    def config_stage(self, stage: str) -> dict:
        return self.read_file(f'config/stages/{stage}.json')

    def state_fleet(self) -> dict:
        return self.read_file('state/fleet.json')

    def write_state_fleet(self, fleet_data: dict) -> None:
        self.write_file('state/fleet.json', fleet_data)
```

## New Class: Service__Vault__Twin

**Path:** `sg_send_deploy/vault/Service__Vault__Twin.py`

An in-memory twin of `Service__Vault` for unit tests. No network calls, no filesystem
interaction beyond what's set up in the test. Follows the established twin pattern.

```python
from osbot_utils.type_safe.Type_Safe import Type_Safe


class Service__Vault__Twin(Type_Safe):
    """In-memory twin of Service__Vault. Holds files as a dict of path -> dict."""
    files        : dict
    configured   : bool = True
    write_enabled: bool = True

    def setup(self) -> 'Service__Vault__Twin':
        return self

    def is_configured(self) -> bool:
        return self.configured

    def can_write(self) -> bool:
        return self.configured and self.write_enabled

    def clone_or_pull(self) -> dict:
        return dict(added=[], modified=[], deleted=[])

    def read_file(self, relative_path: str) -> dict:
        return self.files.get(relative_path, {})

    def write_file(self, relative_path: str, data: dict) -> None:
        self.files[relative_path] = data

    def push(self) -> dict:
        return dict(added=[], modified=[], deleted=[])

    def status(self) -> dict:
        return dict(added=[], modified=[], deleted=[], clean=True)

    def list_files(self) -> list:
        return sorted(self.files.keys())

    def config_ec2(self) -> dict:
        return self.read_file('config/ec2.json')

    def config_budget(self) -> dict:
        return self.read_file('config/budget.json')

    def config_stage(self, stage: str) -> dict:
        return self.read_file(f'config/stages/{stage}.json')

    def state_fleet(self) -> dict:
        return self.read_file('state/fleet.json')

    def write_state_fleet(self, fleet_data: dict) -> None:
        self.write_file('state/fleet.json', fleet_data)

    # --- test helper ---
    def seed(self, relative_path: str, data: dict) -> 'Service__Vault__Twin':
        self.files[relative_path] = data
        return self
```

## New Class: Routes__Vault

**Path:** `sg_send_deploy/vault/Routes__Vault.py`

FastAPI routes that expose vault contents to the admin UI and to other services.
All routes are **read-only by default.** Write routes (sync push, config update) require
admin auth and `can_write()` to be true.

```python
from osbot_fast_api.api.routes.Fast_API__Routes import Fast_API__Routes
from sg_send_deploy.vault.Service__Vault         import Service__Vault

TAG__ROUTES_VAULT = 'vault'

ROUTES_PATHS__VAULT = [
    f'/{TAG__ROUTES_VAULT}/status'             ,
    f'/{TAG__ROUTES_VAULT}/files'              ,
    f'/{TAG__ROUTES_VAULT}/sync'               ,
    f'/{TAG__ROUTES_VAULT}/config/ec2'         ,
    f'/{TAG__ROUTES_VAULT}/config/budget'      ,
    f'/{TAG__ROUTES_VAULT}/config/stage/{{stage}}',
    f'/{TAG__ROUTES_VAULT}/state/fleet'        ,
]


class Routes__Vault(Fast_API__Routes):
    tag           : str          = TAG__ROUTES_VAULT
    service_vault : Service__Vault

    def status(self) -> dict:                                    # GET /vault/status
        return dict(configured  = self.service_vault.is_configured(),
                    can_write   = self.service_vault.can_write()      )

    def files(self) -> list:                                     # GET /vault/files
        if not self.service_vault.is_configured():
            return []
        return self.service_vault.list_files()

    def sync(self) -> dict:                                      # POST /vault/sync
        if not self.service_vault.is_configured():
            return dict(status='error', message='Vault not configured')
        result = self.service_vault.clone_or_pull()
        return dict(status='ok', **result)

    def config__ec2(self) -> dict:                               # GET /vault/config/ec2
        return self.service_vault.config_ec2()

    def config__budget(self) -> dict:                            # GET /vault/config/budget
        return self.service_vault.config_budget()

    def config__stage__stage(self, stage: str) -> dict:          # GET /vault/config/stage/{stage}
        if stage not in ('dev', 'qa', 'prod'):
            return dict(status='error', message=f'Unknown stage: {stage}')
        return self.service_vault.config_stage(stage)

    def state__fleet(self) -> dict:                              # GET /vault/state/fleet
        return self.service_vault.state_fleet()

    def setup_routes(self):
        self.add_route_get  (self.status           )
        self.add_route_get  (self.files            )
        self.add_route_post (self.sync             )
        self.add_route_get  (self.config__ec2      )
        self.add_route_get  (self.config__budget   )
        self.add_route_get  (self.config__stage__stage)
        self.add_route_get  (self.state__fleet     )
        return self
```

## Wire-up: Fast_API__SG_Send__Deploy

Add `Service__Vault` to the app and mount `Routes__Vault`. The vault service also needs
to be injected into `Service__EC2_Instances` and `Operation__EC2__Ephemeral__LLM` so they
can read live config rather than using hardcoded defaults.

```python
# Fast_API__SG_Send__Deploy.setup()

from sg_send_deploy.vault.Service__Vault  import Service__Vault
from sg_send_deploy.vault.Routes__Vault   import Routes__Vault

class Fast_API__SG_Send__Deploy(Serverless__Fast_API):
    service_vault     : Service__Vault          = None
    service_instances : Service__EC2_Instances  = None
    llm_operation     : Operation__EC2__Ephemeral__LLM = None

    def setup(self):
        # 1. Vault first — everything else reads from it
        if self.service_vault is None:
            self.service_vault = Service__Vault()
            self.service_vault.setup()
            if self.service_vault.is_configured():
                self.service_vault.clone_or_pull()   # sync on startup

        # 2. Budget config from vault (falls back to defaults if vault not configured)
        budget_data = self.service_vault.config_budget()
        ec2_data    = self.service_vault.config_ec2()

        # 3. Build EC2 service with vault-sourced config
        if self.service_instances is None:
            budget_config = EC2_Budget_Config(**budget_data) if budget_data else EC2_Budget_Config()
            self.service_instances = Service__EC2_Instances(
                budget_service = Service__EC2_Budget(config=budget_config))

        # ... rest of setup unchanged

    def setup_routes(self):
        self.setup_static_routes()
        self.add_routes(Routes__Info                                        )
        self.add_routes(Routes__Set_Cookie                                  )
        self.add_routes(Routes__EC2_Instances,
                        service_instances = self.service_instances          )
        self.add_routes(Routes__Workflows,
                        operation         = self.llm_operation              )
        self.add_routes(Routes__Vault,
                        service_vault     = self.service_vault              )  # NEW
```

## Integrating Vault Config into Existing Services

Once the vault is loaded, existing services should read from it rather than from hardcoded
defaults. The pattern is: vault config → constructor kwargs → Type_Safe schema. No service
directly reads env vars or the vault; they receive config objects.

### EC2 config from vault

`Operation__EC2__Ephemeral__LLM` currently has `ami_id` and `security_group_id` as
constructor params that callers must supply. After vault integration, the deploy app
reads these from the vault and injects them:

```python
ec2_config  = self.service_vault.config_ec2()
llm_operation = Operation__EC2__Ephemeral__LLM(
    ec2_provider      = self.service_instances.ec2_provider,
    audit_trail       = self.service_instances.audit_trail ,
    security_group_id = ec2_config.get('security_group_id', ''),
)
```

The `ami_id` is passed per-request (it may vary by model), but the SG ID and other
infra-level config are vault-sourced.

## Admin UI Component: deploy-vault-panel

**Path:** `sg_send_deploy__ui__admin/v0/v0.1/v0.1.2/deploy-vault-panel.js`

A vanilla JS Web Component following IFD methodology (zero framework dependencies).

**Panels to render:**

1. **Connection status** — `GET /vault/status` → green/amber/red badge
   - Green: configured + can_write
   - Amber: configured, read-only
   - Red: not configured

2. **File browser** — `GET /vault/files` → sorted list of paths

3. **EC2 config viewer** — `GET /vault/config/ec2` → read-only JSON card

4. **Budget config viewer** — `GET /vault/config/budget` → read-only JSON card
   (highlight `enforce_limits: false` in amber as a warning)

5. **Stage config tabs** — `GET /vault/config/stage/{dev|qa|prod}` → tabs with JSON

6. **Fleet state viewer** — `GET /vault/state/fleet` → table of instances

7. **Sync button** — `POST /vault/sync` → shows diff (added/modified/deleted files)

**Component name:** `<deploy-vault-panel>`

**Attribute:** `api-base` — base URL for API calls (defaults to current origin)

Do not implement write-back to vault via the UI in this phase. Read + sync only.

## Tests Required

**Path:** `tests/unit/vault/`

All tests use `Service__Vault__Twin` — no network calls, no real vault.

| Test file | Covers |

```python
class test__Routes__Vault__with_twin(TestCase):
```

## Architectural Note: Why Not `Secrets__Store`?

`sg_send_cli.secrets.Secrets__Store` is an encrypted key-value store that lives on the
local filesystem (not the vault). It requires a separate passphrase for its own encryption
layer. It is **not** used here.

The deploy vault holds JSON config files, not individual secrets. Config is structured,
auditable, and diff-able. If individual secrets (per-instance SSH keys, external API tokens)
need to be stored later, `Secrets__Store` inside the vault directory is the right tool —
but that is a follow-on brief.
