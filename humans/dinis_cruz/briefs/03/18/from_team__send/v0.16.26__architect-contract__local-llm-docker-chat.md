# Architect Contract — Local LLM Docker Chat
**SG_Send__Deploy · Response to v0.1.13 Technical Brief**
Version v0.16.26 · 18 March 2026 · Architect (SGraph Send Explorer Team)

---

## 1. Purpose

This document defines the API contracts, Type_Safe schemas, route classes, and service boundaries for the Local LLM Docker Chat module described in `v0.1.13__technical-brief__local-llm-docker-chat.md`. It replaces the raw FastAPI patterns proposed in that brief with the standard SG/Send stack patterns.

**The deploy team should treat this as the architectural specification.** The schemas, class names, and route signatures are contracts. Implementation details within each service method are Dev's domain.

---

## 2. What Changes From the Original Brief

| Original Brief (v0.1.13) | This Contract | Why |
|---|---|---|
| Raw `fastapi` + `uvicorn` in `requirements.txt` | `osbot-fast-api`, `osbot-fast-api-serverless`, `osbot-utils`, `memory-fs`, `httpx` | Stack compliance. Same route classes work when mounted into Lambda later. |
| `server.py` creates `FastAPI()` directly | `Fast_API__Local_LLM(Serverless__Fast_API)` | Standard entry point. Provides auto-wiring, middleware, MCP mount, test infrastructure. |
| `routes/chat.py`, `models.py`, `sessions.py` as plain modules | `Routes__Chat`, `Routes__Models`, `Routes__Sessions` classes extending `Fast_API__Routes` | Standard routing with `setup_routes()`, auto path generation, Type_Safe integration. |
| JSON session files via raw `json.load/dump` | `Service__Chat__Sessions(Type_Safe)` using `Storage_FS` | Pluggable backend. Memory for tests, disk for Docker, S3 if ever deployed to Lambda. |
| Session JSON format as informal spec | `Schema__Chat__Session(Type_Safe)` with typed fields | Runtime enforcement, clean serialisation, round-trip safety. |
| `httpx.AsyncClient` created per-request | `Service__Ollama__Proxy(Type_Safe)` with persistent client | Testable, injectable, lifecycle-managed. |

**What does NOT change:** Docker networking, sg-layout bundling, offline constraint, volume mounts, `host.docker.internal` for Ollama, vanilla Web Components on the frontend. The Architect has no objections to any of those decisions.

## 4. Type_Safe Schemas

### 4.1 Named Types (`schemas/types/`)

```python
# Chat__Session_Id.py
from osbot_utils.type_safe.primitives.domains.identifiers.Obj_Id import Obj_Id

class Chat__Session_Id(Obj_Id): pass                         # 8-char hex, auto-generates


# Enum__LLM__Role.py
from enum import Enum

class Enum__LLM__Role(str, Enum):
    SYSTEM    = "system"
    USER      = "user"
    ASSISTANT = "assistant"
    TOOL      = "tool"

    def __str__(self): return self.value


# Enum__Chat__Session_Status.py
from enum import Enum

class Enum__Chat__Session_Status(str, Enum):
    ACTIVE   = "active"
    ARCHIVED = "archived"

    def __str__(self): return self.value


# collections.py
from osbot_utils.type_safe.type_safe_core.collections.Type_Safe__List import Type_Safe__List

class List__Chat__Messages(Type_Safe__List):
    expected_type = None                                     # set after Schema__Chat__Message is defined
    # See note in §4.2 on how to resolve this circular reference
```

**Circular reference resolution for `List__Chat__Messages`:** Define the collection in the same file as `Schema__Chat__Message`, or set `expected_type` at module level after the schema import. The pattern used in SG/Send is to put the collection in the same module as the schema it contains:

```python
# Schema__Chat__Message.py — collection defined AFTER the schema
class Schema__Chat__Message(Type_Safe): ...

class List__Chat__Messages(Type_Safe__List):
    expected_type = Schema__Chat__Message
```

from osbot_utils.type_safe.primitives.domains.llm.safe_str              \

    role    : Enum__LLM__Role                                # user, assistant, system, tool

**Note on `Safe_Str__LLM__Prompt`:** This has a 32KB `max_length`. LLM responses can exceed this for very long generations. If real-world usage shows truncation, create a local `Safe_Str__LLM__Response` with a higher limit (e.g., 128KB). Test with real Ollama output before shipping.

## 5. Service Classes

### 5.1 Service__Chat__Sessions

```python
# Service__Chat__Sessions.py
from memory_fs.storage_fs.Storage_FS                                     import Storage_FS
from memory_fs.storage_fs.providers.Storage_FS__Memory                   import Storage_FS__Memory
from osbot_utils.type_safe.Type_Safe                                     import Type_Safe
from osbot_utils.type_safe.primitives.domains.identifiers.Timestamp_Now  import Timestamp_Now
from osbot_utils.type_safe.type_safe_core.decorators.type_safe           import type_safe
from osbot_utils.utils.Json                                              import json_loads, json_dumps
from sg_send_deploy_local_llm.schemas.types.Chat__Session_Id             import Chat__Session_Id
from sg_send_deploy_local_llm.schemas.Schema__Chat__Session              import Schema__Chat__Session

class Service__Chat__Sessions(Type_Safe):                    # Session CRUD against Storage_FS
    storage_fs : Storage_FS = None                           # pluggable backend

    def __init__(self, **kwargs):
        super().__init__(**kwargs)
        if self.storage_fs is None:
            self.storage_fs = Storage_FS__Memory()

    def session_path(self, session_id):                      # Storage path for a session
        return f'sessions/{session_id}.json'

    @type_safe
    def create(self, session: Schema__Chat__Session) -> Schema__Chat__Session:
        data = json_dumps(session.json())                    # Type_Safe → dict → JSON string
        self.storage_fs.file__save(self.session_path(session.id),
                                   data.encode())
        return session

    @type_safe
    def get(self, session_id: Chat__Session_Id) -> Schema__Chat__Session:
        raw = self.storage_fs.file__json(self.session_path(session_id))
        if not raw:
            return None
        return Schema__Chat__Session.from_json(raw)

    @type_safe
    def update(self, session: Schema__Chat__Session) -> Schema__Chat__Session:
        session.updated_at = Timestamp_Now()
        return self.create(session)                          # overwrite

    @type_safe
    def delete(self, session_id: Chat__Session_Id) -> bool:
        path = self.session_path(session_id)
        if self.storage_fs.file__exists(path):
            self.storage_fs.file__delete(path)
            return True
        return False

    def list_sessions(self) -> list:                         # Returns list of session summaries
        files = self.storage_fs.folder__files('sessions/')
        sessions = []
        for path in (files or []):
            raw = self.storage_fs.file__json(path)
            if raw:
                session = Schema__Chat__Session.from_json(raw)
                sessions.append(dict(id            = str(session.id)         ,
                                     title         = str(session.title)      ,
                                     model         = str(session.model)      ,
                                     created_at    = int(session.created_at) ,
                                     message_count = len(session.messages)   ))
        return sorted(sessions, key=lambda s: s['created_at'], reverse=True)
```

**Key design decision:** `Storage_FS` is the abstraction. In Docker, use `Storage_FS__Disk` pointed at `/app/data`. In tests, use `Storage_FS__Memory`. If this ever moves to Lambda, use the S3 backend. Application code is identical in all cases.

### 5.2 Service__Ollama__Proxy

```python
# Service__Ollama__Proxy.py
import httpx
from typing                                                              import AsyncIterator
from osbot_utils.type_safe.Type_Safe                                     import Type_Safe
from osbot_utils.type_safe.primitives.domains.web.safe_str.Safe_Str__Url import Safe_Str__Url
from osbot_utils.type_safe.primitives.domains.llm.safe_str               \
    .Safe_Str__LLM__Model_Id                                             import Safe_Str__LLM__Model_Id
from osbot_utils.utils.Json                                              import json_loads

class Service__Ollama__Proxy(Type_Safe):                     # Streaming proxy to Ollama
    ollama_url : Safe_Str__Url = 'http://localhost:11434'    # overridden by OLLAMA_HOST env var

    async def stream_chat(self, request_body: dict) -> AsyncIterator[bytes]:
        async with httpx.AsyncClient(timeout=300.0) as client:
            async with client.stream('POST',
                                     f'{self.ollama_url}/api/chat',
                                     json=request_body) as response:
                async for chunk in response.aiter_bytes():
                    yield chunk

    async def list_models(self) -> list:                     # Returns raw model list from Ollama
        async with httpx.AsyncClient(timeout=30.0) as client:
            response = await client.get(f'{self.ollama_url}/api/tags')
            data     = json_loads(response.text)
            return data.get('models', [])
```

**Why `httpx.AsyncClient` is created per-call:** FastAPI route methods can be async. The Ollama proxy uses async streaming. Creating a persistent `AsyncClient` requires lifecycle management (startup/shutdown events). Per-call creation is simpler and correct for a single-user local tool. If performance becomes an issue, promote to a lifespan-managed client — but not before measuring.

**Why `request_body` is `dict` not `Schema__Chat__Request`:** The streaming proxy forwards the body to Ollama verbatim. Type validation happens at the route layer. The service just proxies bytes.

## 6. Route Classes

### 6.1 Routes__Chat

```python
# Routes__Chat.py
from fastapi                                                             import Request
from fastapi.responses                                                   import StreamingResponse
from osbot_fast_api.api.routes.Fast_API__Routes                          import Fast_API__Routes
from sg_send_deploy_local_llm.service.Service__Ollama__Proxy             import Service__Ollama__Proxy

TAG__ROUTES_CHAT = 'api/chat'

ROUTES_PATHS__CHAT = [f'/{TAG__ROUTES_CHAT}']

class Routes__Chat(Fast_API__Routes):                        # POST /api/chat — streaming LLM proxy
    tag           : str = TAG__ROUTES_CHAT
    ollama_proxy  : Service__Ollama__Proxy                   # auto-initialized by Type_Safe

    def chat(self, request: Request) -> StreamingResponse:   # POST /api/chat
        import asyncio
        body = asyncio.get_event_loop().run_until_complete(
            request.json())                                  # parse JSON body
        return StreamingResponse(
            self.ollama_proxy.stream_chat(body),
            media_type='application/x-ndjson')

    def setup_routes(self):
        self.add_route_post(self.chat)
        return self
```

**IMPORTANT — async route pattern:** The standard `Fast_API__Routes.add_route_post()` registers a sync handler. For streaming, you may need to register the route directly on the FastAPI app using `self.app().add_api_route()` with an `async def` handler. Test this — if `add_route_post` doesn't support `StreamingResponse` correctly, use:

```python
def setup_routes(self):
    self.app().add_api_route(
        path     = f'/{self.tag}',
        endpoint = self._async_chat,
        methods  = ['POST'],
        tags     = [self.tag])
    return self

async def _async_chat(self, request: Request) -> StreamingResponse:
    body = await request.json()
    return StreamingResponse(
        self.ollama_proxy.stream_chat(body),
        media_type='application/x-ndjson')
```

This is the one genuinely novel pattern in this module. **Dev should verify which registration method works and document the finding.**

### 6.3 Routes__Sessions

```python
# Routes__Sessions.py
from fastapi                                                             import HTTPException
from osbot_fast_api.api.routes.Fast_API__Routes                          import Fast_API__Routes
from sg_send_deploy_local_llm.schemas.types.Chat__Session_Id             import Chat__Session_Id
from sg_send_deploy_local_llm.schemas.Schema__Chat__Session              import Schema__Chat__Session
from sg_send_deploy_local_llm.service.Service__Chat__Sessions            import Service__Chat__Sessions

TAG__ROUTES_SESSIONS = 'api/sessions'

ROUTES_PATHS__SESSIONS = [f'/{TAG__ROUTES_SESSIONS}'                        ,
                          f'/{TAG__ROUTES_SESSIONS}/{{session_id}}'         ]

class Routes__Sessions(Fast_API__Routes):                    # Session CRUD
    tag             : str = TAG__ROUTES_SESSIONS
    session_service : Service__Chat__Sessions

    def sessions(self) -> list:                              # GET /api/sessions — list all
        return self.session_service.list_sessions()

    def sessions__session_id(self, session_id: str) -> dict: # GET /api/sessions/{session_id}
        session = self.session_service.get(Chat__Session_Id(session_id))
        if session is None:
            raise HTTPException(status_code=404, detail='Session not found')
        return session.json()

    def create(self, session: Schema__Chat__Session          # POST /api/sessions — create/save
               ) -> dict:
        result = self.session_service.create(session)
        return result.json()

    def update__session_id(self, session_id: str,            # PUT /api/sessions/{session_id}
                                 session: Schema__Chat__Session
                           ) -> dict:
        session.id = Chat__Session_Id(session_id)            # ensure ID matches path
        result = self.session_service.update(session)
        return result.json()

    def delete__session_id(self, session_id: str) -> dict:   # DELETE /api/sessions/{session_id}
        deleted = self.session_service.delete(Chat__Session_Id(session_id))
        if not deleted:
            raise HTTPException(status_code=404, detail='Session not found')
        return dict(deleted=True, session_id=session_id)

    def setup_routes(self):
        self.add_route_get   (self.sessions)
        self.add_route_get   (self.sessions__session_id)
        self.add_route_post  (self.create)
        self.add_route_put   (self.update__session_id)
        self.add_route_delete(self.delete__session_id)
        return self
```

## 7. FastAPI App Class

```python
# Fast_API__Local_LLM.py
from osbot_fast_api_serverless.fast_api.Serverless__Fast_API            import Serverless__Fast_API
from osbot_fast_api_serverless.fast_api.routes.Routes__Info             import Routes__Info
from osbot_utils.utils.Env                                              import get_env
from sg_send_deploy_local_llm.fast_api.routes.Routes__Chat             import Routes__Chat
from sg_send_deploy_local_llm.fast_api.routes.Routes__Models           import Routes__Models
from sg_send_deploy_local_llm.fast_api.routes.Routes__Sessions         import Routes__Sessions
from sg_send_deploy_local_llm.service.Service__Chat__Sessions          import Service__Chat__Sessions
from sg_send_deploy_local_llm.service.Service__Ollama__Proxy           import Service__Ollama__Proxy

class Fast_API__Local_LLM(Serverless__Fast_API):
    session_service : Service__Chat__Sessions = None
    ollama_proxy    : Service__Ollama__Proxy  = None

    def setup(self):
        with self.config as _:
            _.name        = 'SG Local LLM'
            _.version     = 'v0.1.13'
            _.description = 'Local LLM chat via Ollama'
            _.enable_cors = True                             # browser → container
            _.enable_api_key = False                         # no auth for local tool

        ollama_url = get_env('OLLAMA_HOST', 'http://localhost:11434')

        if self.ollama_proxy is None:
            self.ollama_proxy = Service__Ollama__Proxy(ollama_url=ollama_url)

        if self.session_service is None:
            from memory_fs.storage_fs.providers.Storage_FS__Disk import Storage_FS__Disk
            storage = Storage_FS__Disk(root_path='/app/data')    # Docker volume mount
            self.session_service = Service__Chat__Sessions(storage_fs=storage)

        return super().setup()

    def setup_routes(self):
        self.add_routes(Routes__Info)
        self.add_routes(Routes__Chat    , ollama_proxy    = self.ollama_proxy   )
        self.add_routes(Routes__Models  , ollama_proxy    = self.ollama_proxy   )
        self.add_routes(Routes__Sessions, session_service = self.session_service)

    def setup_static(self):                                  # Mount static files for the UI
        from fastapi.staticfiles import StaticFiles
        self.app().mount('/static', StaticFiles(directory='static'), name='static')
```

## 9. Open Questions for Dev

1. **Async route registration:** Does `Fast_API__Routes.add_route_post()` work with `async def` handlers returning `StreamingResponse`? If not, use direct `app().add_api_route()`. **This must be tested first** — it determines the `Routes__Chat` implementation.

2. **`Storage_FS__Disk` API:** Verify `file__json()`, `file__save()`, `file__delete()`, and `folder__files()` work correctly with the disk provider and the `sessions/` subfolder. The memory provider is well-tested; disk provider may have edge cases around missing directories.

3. **`Safe_Str__LLM__Prompt` max_length:** Test with a real Ollama response from `gemma3:4b` generating a long response. If truncated at 32KB, create `Safe_Str__LLM__Response(Safe_Str)` with `max_length = 131072`.

4. **Session title auto-generation:** The brief says "first ~50 chars of first user message". Implement in `Routes__Sessions.create()` — if `session.title` is empty, derive from `session.messages[0].content[:50]`.

## 10. Boundary Rules

| Boundary | Rule |
|---|---|
| Route → Service | Routes call service methods. Routes handle HTTP concerns (status codes, headers, streaming). Routes never access Storage_FS directly. |
| Service → Storage | Services call Storage_FS methods. Services never know if the backend is memory, disk, or S3. |
| Schema → nothing | Schemas are pure data containers. No methods. No imports of services or storage. |
| Ollama proxy → Ollama | The proxy translates between FastAPI and Ollama's HTTP API. It does not validate message content — that's the schema's job at the route layer. |
